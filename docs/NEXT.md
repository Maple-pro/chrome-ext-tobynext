看完项目后，我觉得 TobyNext 的核心已经很完整：工作区/空间集合管理、窗口与标签组保存、拖拽整理、全局搜索、Chrome 书签同步、Toby 导入都有了。

下一阶段最值得做的，不是继续堆层级，而是提升“保存、恢复、找回”这条主链路。

## 第一优先级：明显提升日常体验

1. 集合恢复模式

目前“打开集合”会创建一个新窗口，可以增加：

- 在当前窗口打开
- 在新窗口打开
- 恢复为 Chrome 标签组
- 打开后自动归档或删除集合
- 跳过已经打开的重复标签

这是最贴合产品定位的一组增强。

2. 删除撤销与回收站

现在删除集合使用 removeTree，误删后恢复比较困难。建议提供：

- 删除后的 Toast：“已删除，撤销”
- 本地保存最近删除记录
- 一个简单的回收站页面
- 延迟若干秒后才真正删除

这是高价值、实现成本也相对低的功能。

3. 重复标签检测

在保存窗口、标签组或拖入标签时检测：

- 当前集合内是否已存在
- 当前 Space 内是否已存在
- 当前浏览器是否已经打开
- 允许用户选择“跳过、保留、移动到已有项”

标签管理工具很容易积累重复内容，这会是一个很实用的差异化功能。

4. 快捷保存入口

现在 Popup 基本只是“打开管理器”，可以让它真正有用：

- 保存当前标签
- 保存当前窗口
- 保存当前标签组
- 选择目标 Workspace / Space / Collection
- “快速收纳”：保存当前窗口并关闭原标签

这样用户不用先打开新标签页再操作。

5. 键盘快捷键与命令面板

例如：

- Ctrl/Cmd + K：全局搜索
- Ctrl/Cmd + Shift + S：保存当前窗口
- N：新建集合
- Enter：打开选中项
- 方向键浏览结果
- Chrome Commands API 提供全局快捷键

对于重度标签用户，这项提升非常明显。

## 第二优先级：让内容更容易找

6. 升级全局搜索

现有搜索依赖 chrome.bookmarks.search，可以进一步加入：

- 显示结果所属的 Workspace / Space / Collection 路径
- 按标题、域名、URL 筛选
- 搜索集合名称
- 最近访问排序
- 搜索后直接定位到对应集合
- 搜索当前打开的标签
- 键盘选择和快速打开

尤其是“显示路径”，否则同名网页多了以后很难判断它存在哪里。

7. 标签与收藏元数据

在 Chrome 书签之外，用 storage.local 保存附加信息：

- 标签/关键词
- 备注
- 收藏星标
- 创建时间、最近打开时间
- 打开次数
- 自定义颜色或图标

书签继续作为真实数据源，元数据只负责增强体验，不破坏现有的同步方案。

8. 智能集合

让集合支持动态规则，例如：

- 域名是 github.com
- 标题包含某个关键词
- 最近七天保存
- 尚未阅读
- 经常打开
- 疑似重复

它更像“保存的搜索条件”，不必真的移动底层书签。

9. 最近使用和收藏置顶

增加首页区域：

- 最近打开的集合
- 最近保存的标签
- 常用集合
- 星标集合
- “继续上次工作”

这个比让用户每次逐层寻找效率高很多。

## 第三优先级：恢复现场与自动化

10. 真正的会话快照

除了 URL，还记录：

- 标签顺序
- 标签组名称和颜色
- 固定标签
- 当前激活标签
- 窗口之间的归属
- 保存时间

恢复时尽可能还原原始工作现场。这个功能很适合成为 TobyNext 的核心卖点。

11. 自动保存与崩溃恢复

可以提供可选策略：

- 每隔一段时间保存
- 关闭窗口时自动保存
- 浏览器启动后提示恢复
- 只保留最近若干快照
- 自动排除新标签页和敏感页面

需要注意避免产生大量书签；自动快照更适合先放在 storage.local，用户确认后再永久归档。

12. 打开集合时恢复标签组

项目已经能够读取 Chrome 标签组，因此可以反向恢复：

- 保存标签组标题和颜色
- 打开集合后调用 Tab Groups API 分组
- 多个已保存标签组恢复到同一窗口
- 无分组标签保持原顺序

13. 定时打开工作区

例如：

- 每周一上午打开“周会”
- 工作日上午打开“工作台”
- 指定时间提醒恢复某个集合

这需要 alarms 权限，建议作为明确的可选功能。

## 产品完整性功能

14. 正式的设置页面

当前 Options 页面还是示例按钮，可以替换为真正的设置中心：

- 默认打开方式
- 打开集合后是否关闭管理页
- 是否去重
- 是否关闭保存后的原标签
- 主题和语言
- 自动保存设置
- 搜索范围
- 导入、导出、备份和诊断

15. 数据导入导出

除了 Toby 导入，还可以支持：

- TobyNext JSON 备份/恢复
- Chrome bookmarks HTML
- CSV
- Raindrop、OneTab、Session Buddy 等格式
- 导入预览与冲突处理

16. 深色模式和布局密度

- 跟随系统主题
- 紧凑/舒适显示
- 调整左右侧栏宽度
- 隐藏不常用面板
- 记住集合展开状态

17. 多语言

界面目前主要是英文，而项目已有中文 README。可以抽取文案，优先支持：

- 简体中文
- 英文
- 跟随浏览器语言

18. 健康检查

扫描并处理：

- 重复链接
- 已失效网页
- URL 重定向
- 空集合
- 长期未使用内容
- 无法加载的 favicon

失效链接检测需要网络请求和隐私说明，可以做成用户主动触发。

## 我建议的实施顺序

如果准备做一个近期版本，我会选择：

1. 删除撤销
2. Popup 快速保存
3. 搜索结果显示所在路径，并支持定位
4. 集合打开方式与重复标签处理
5. 正式的设置页
6. 标签组完整保存与恢复

这六项互相之间依赖不重，能连续交付，而且用户会比较直观地感受到产品成熟度。

如果只选一个作为下一项，我最推荐“Popup 快速保存”。现有 Popup 几乎还是空白，而相关保存逻辑已经存在，开发成本不高，却能把最常用操作从多步缩短为一次点击。
